# Synaq на Vercel и телефоне

Один сайт обслуживает телефон и компьютер. Vercel запускает Next.js и API;
аккаунты, попытки и результаты хранятся в отдельной облачной PostgreSQL.
Компьютер разработчика не должен оставаться включённым. Для пробников нужен интернет.

## Первое размещение

1. В Vercel импортируйте `bekw-eg/Synaq` из GitHub. Репозиторий раньше назывался
   `EntTIPO-education`, текущий адрес — `https://github.com/bekw-eg/Synaq`.
2. Выберите ветку `feature/vercel-mobile-web`, содержащую подготовку к размещению
   и актуальный банк заданий. Для автоматических production-обновлений укажите её
   в **Settings → Environments → Production → Branch Tracking**. Если изменения
   позднее объединены в `main`, переключите отслеживаемую ветку на `main`.
3. Framework — **Next.js**, Root Directory — корень репозитория, Node.js — **22.x**.
   `vercel.json` задаёт `npm ci` и `npm run build`. Перед сборкой автоматически
   генерируется Prisma Client и иконки. Output Directory оставьте стандартным.
4. Создайте PostgreSQL через **Storage → Create Database** (например, Neon)
   или подключите существующую облачную PostgreSQL. Используйте адрес провайдера,
   предназначенный для Prisma и серверных подключений. `localhost:5433` из
   локального `.env` не доступен из Vercel.
5. В **Settings → Environment Variables** добавьте переменные из таблицы.
   Подготовьте базу по следующему разделу, затем запустите production-размещение.

| Переменная | Значение | Окружение |
| --- | --- | --- |
| `DATABASE_URL` | Приватная строка подключения облачной PostgreSQL | Production |
| `SESSION_SECRET` | Случайный приватный секрет, не менее 32 байт | Production |
| `ENABLE_DEMO_MODE` | `false` | Production |

`DATABASE_URL` и `SESSION_SECRET` храните как секреты Vercel, без префикса
`NEXT_PUBLIC_`. Постоянный секрет сохраняет действительность входа после
повторных сборок. Для Preview используйте отдельную базу и отдельный секрет.
`.env` не загружайте в GitHub или Vercel как файл: `.vercelignore` исключает
локальные файлы окружения из CLI-загрузки.

Текущий публичный пробник не требует `MATH_SERVICE_URL` или `GEMINI_API_KEY`:
Docker-сервисы для отложенных учебных разделов на Vercel не переносятся.

## Новая пустая база

В PowerShell этого checkout установите `$env:DATABASE_URL` на приватную строку
подключения **новой пустой облачной базы**. Переменная окружения имеет приоритет
над локальным `.env`. Затем выполните:

```powershell
npm ci
npm run db:generate
npx prisma db push
npx prisma db execute --schema prisma/schema.prisma --file prisma/updates/20261004_exam_mode.sql
npx prisma db execute --schema prisma/schema.prisma --file prisma/updates/20261010_exam_bank_audit.sql
npm run db:seed
```

`db push` создаёт таблицы, первый SQL-файл добавляет частичный уникальный индекс
одной активной попытки на аккаунт, второй добавляет структуры аудита и повторного
запуска. Seed создаёт учебные темы и проверенный RU/KK банк. Демо-профиль из seed
не доступен для входа, когда `ENABLE_DEMO_MODE=false`.

Эти действия выполняются один раз для новой базы, отдельно от сборки Vercel.
Для базы с данными применяйте нужные аддитивные SQL-обновления и `npm run db:exam`;
не используйте reset, принудительное принятие потери данных или общий seed.
Локальные аккаунты и историю в облачную базу этот процесс не переносит.

Если начальная загрузка с компьютера прерывается из-за задержек сети, после
создания схемы и базовых тем можно выполнить `npm run db:cloud:init` на сервере
рядом с базой. Команда использует `DATABASE_URL_UNPOOLED`, продолжает импорт
по стабильным ID и отказывается работать при наличии реальных пользователей,
попыток или ответов. Для разовой инициализации используйте служебное размещение
копии исходников с `buildCommand: "npm run build && npm run db:cloud:init"`
в её `vercel.json`. После импорта публикуйте обычные исходники с `npm run build`;
служебную сборку не используйте для дальнейших обновлений.

## Проверка размещения

Откройте production-ссылку в приватном окне браузера телефона. Проверьте
регистрацию, запуск пробника на RU и KK, сохранение ответа, продолжение после
перезагрузки, завершение и запись результата. Ссылкой должен быть доступен
production-сайт; защищённая Preview-ссылка может требовать входа в Vercel.

## Значок на главном экране

- Android / Chrome: меню **⋮ → Добавить на главный экран → Установить**.
  Если браузер предлагает только ярлык, его тоже можно добавить.
- iPhone / Safari: **Поделиться → На экран «Домой» → Добавить**.

Manifest подключён к страницам и задаёт отдельное окно приложения. На iPhone
включён режим веб-приложения. Подсказки доступны также на странице «Аккаунт».
После первого запуска со значка может потребоваться вход; результаты остаются
привязаны к тому же аккаунту. Установка не добавляет офлайн-пробники.

Основания настройки: [Next.js на Vercel](https://vercel.com/docs/frameworks/full-stack/nextjs),
[генерация Prisma Client при сборке](https://www.prisma.io/docs/orm/v7/more/troubleshooting/nextjs#vercel-build-dependency-caching),
[облачные базы Vercel](https://vercel.com/docs/storage).
